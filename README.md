# docs/archive —— 归档目录

本目录存放**已完成使命、不再随代码演进**的文档，与 `docs/` 下的**活跃文档**分开，避免主目录堆积历史稿件、干扰阅读主路径。

## 什么该放进来

- **已整改完毕的临时笔记**：如 review 报告——里面列的问题全部改完并落地后，把报告移进本目录归档，标注完成日期即可。
- **被取代的旧方案/草案**：新方案定稿后，旧版设计稿移入归档，保留历史脉络。
- **一次性计划文档**：某个阶段性计划执行完毕后归档。

## 什么不该放

- 仍在被代码/配置**硬引用**的文档（文件名被 `.py` 注释、`.yaml` 引用的，移动会导致引用失效——移动前先 grep 确认无引用）。
- 仍是权威来源的活跃文档（如 `tech_design.md`）。

## 归档约定

1. **移动而非复制**：用 `git mv docs/<file> docs/archive/<file>` 保留历史，避免两处副本漂移。
2. **移动前先 grep**：确认该文件名没有被源码/配置/其它文档硬引用；有引用先改引用或放弃归档。
3. **在被归档文件顶部加一行归档说明**：`> 已归档（YYYY-MM-DD）：<原因，如"P0/P1 问题已整改并落地">`。
4. 归档是**只读留存**，一般不再修改归档后的文档。
